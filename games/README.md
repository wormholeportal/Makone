# games/

Each file here is **one self-contained, playable game** — a single ES module that
does:

```js
import * as THREE from 'three'
// optional: import { ... } from 'makone/game'  (the bundled runtime toolkit)

export default async function createScene(container) {
  // build the world, wire up input, run your own requestAnimationFrame loop
  return {
    dispose: () => {/* tear everything down */},
    resize: (w, h) => {/* update camera + renderer */},
    // optional: play, pause, getState (see src/types/scenes.ts)
  }
}
```

The default export receives a DOM container and returns a `SceneControls` object.
The host (`src/components/GameCanvas.tsx`) mounts it, keeps it sized, and disposes
it on unmount — the game owns its own loop and input.

## Adding a game

1. Drop `your-game.js` into this folder.
2. Add an entry to `src/games/catalog.ts` (id must match the filename).
3. Open a PR with a short description, controls, and any notable performance
   considerations.

Vite code-splits every `games/*.js` into its own chunk, so visitors only download
the game they open.

## No external assets

These games are **pure procedural code** — geometry, materials, and textures are
all generated at runtime. There are intentionally no `.glb`, `.png`, or audio
files to download, which is what keeps the site light and CDN-friendly.

## Allowed imports

- `three`, `three/addons/*`
- `@dimforge/rapier3d-compat` (physics — opt in only when motion needs it)
- `makone/game` — the small bundled toolkit used by existing games
  (see `src/runtime/game/`)

Community games do not have to be generated by Makone as long as they follow the
same module contract.
